# GERA Launcher — архитектура

Версия документа: 2026-11-14 (этап «собственный лаунчер»).

## 1. Главный принцип

GERA Launcher — самостоятельный лаунчер Minecraft. У Horizon берутся ровно две вещи:

1. **Minecraft Rust Client Horizon** — официальные сборки `horizon-client`.
2. **Horizon Mods Registry** — каталог модов `index.json`.

Официальный `horizon-launcher` (GUI и CLI) не является зависимостью: GERA не запускает его,
не устанавливает, не читает его `settings.json`, сборки и базу данных и не требует его
присутствия в системе.

## 2. Что проверено о Horizon

Источник: <https://github.com/horizon-rust/horizon>, установленная копия и GitHub Releases.

| Факт | Значение |
|---|---|
| Лицензия Horizon | MIT |
| Игра | Minecraft: Java Edition 26.3, переписана на Rust |
| Клиент | Horizon 0.1.0, Launch API 0.1.0 (experimental) |
| Релизы | GitHub Releases: `horizon-linux-x86_64.tar.gz`, `SHA256SUMS`, `nightly`, `v0.2.x` |
| Ресурсы | готовятся `horizon-prepare` из собственной копии Minecraft игрока |
| Java | для запуска не нужна; Java-моды Fabric/NeoForge не работают |
| Моды | контентные `.hmod` (данные), нативные `.hnmod` (сборка Horizon с mixins) |
| Registry | `https://horizon-rust.github.io/horizon-mods/index.json`, schema 1 |

Команда запуска, проверенная на этой машине:

```sh
horizon-client \
  --resources <клиент>/.local/horizon-client/26.3 \
  --game-dir <игровая папка сборки> \
  --home <игровая папка сборки> \
  --name <ник>
```

`HORIZON_OFFLINE_SKIN` передаётся, только если файл скина существует.

## 3. Компоненты GERA

| Модуль | Ответственность |
|---|---|
| `src-tauri/src/clients.rs` | список официальных релизов GitHub, проверка SHA-256, распаковка в папку GERA, запуск `horizon-prepare` |
| `src-tauri/src/mods.rs` | загрузка Registry, кэш, установка/удаление `.hmod`, резервные копии, метаданные |
| `src-tauri/src/net.rs` | HTTPS через системный `curl`, SHA-256 через `sha2` |
| `src-tauri/src/horizon.rs` | обнаружение клиентов (GERA / уже лежащие на диске / своя папка), ресурсы, процессы, Launch API |
| `src-tauri/src/store.rs` | настройки и сборки, атомарный `state.json` |
| `src-tauri/src/commands.rs` | Tauri-команды |

Обнаружение клиентов:

- `~/.local/share/gera-launcher/clients/*` — установлено GERA, полностью управляется ей;
- `~/.local/share/horizon-launcher/versions/*` — **только чтение**: если версия уже лежит
  на диске, GERA может её использовать и показывает источник «на диске»;
- своя папка из настроек — если содержит `horizon-client`.

`settings.json` официального лаунчера не читается. Выбранная версия хранится в сборке GERA.

## 4. Данные GERA

```
~/.local/share/gera-launcher/
├─ state.json                 настройки, сборки, активная сборка
├─ mods-state.json            какие моды поставлены GERA (на сборку)
├─ clients/<тег>/             установленные клиенты Horizon
├─ profiles/<id>/game/        игровые папки новых сборок
├─ backups/mods/              копии заменённых и удалённых .hmod
├─ logs/                      stdout/stderr запусков GERA
└─ cache/                     индекс Registry и скачанные архивы
```

Игровые папки игрока (`~/.local/share/horizon` и другие) не перемещаются. GERA пишет туда
только по явному действию: установка мода в `horizon-mods/` выбранной сборки.

## 5. Моды

- Каталог читается напрямую из Registry: поиск, категории, описание, авторы, версии,
  иконки, совместимость (`game`, `api`), размер и SHA-256.
- Установка `.hmod`: скачивание → проверка SHA-256 → копия в
  `<игровая папка>/horizon-mods/`. Существующий файл сначала уходит в `backups/mods/`.
  Мод удаляется с резервной копией; мир не затрагивается.
- Моды по умолчанию выключены — включает игрок в игре: **Options → Mods** (запись в
  `horizon-mods.txt`). GERA это состояние не подделывает.
- Нативные `.hnmod` меняют исходники Horizon, поэтому GERA собирает под них отдельный
  клиент (`src-tauri/src/native.rs`):
  1. берёт из `api` реестра (`native-1/<horizon>/<mixins>`) или `horizon-native.json`
     точные коммиты;
  2. скачивает архив исходников Horizon с codeload и распаковывает в
     `<данные>/native/source/<commit>`;
  3. собирает `horizon-mixins` (`cargo install --git … --rev …`) в `native/tools/`;
  4. раскладывает `mixins/<id>/` мода и запускает
     `horizon-mixins apply --workspace … --mods … --out …`;
  5. компилирует `cargo build --locked --profile fast -p horizon-client` с одним
     потоком, кэш — `native/target/`. На машинах с менее 6 ГБ памяти сам клиент
     собирается с `opt-level=1` и одним codegen-unit, а если и этого не хватает —
     без оптимизации (зависимости остаются оптимизированными);
  6. кладёт бинарник в `clients/native-<commit>-<hash>/horizon-client`, а ресурсы
     базовой сборки подключает симлинком `.local`, не копируя гигабайты.
- Сборка привязана к коммиту мода. Если базовая версия — другой коммит, GERA
  предупреждает и требует явного «Собрать всё равно». Trait-API моды (`[api]`)
  пока не поддерживаются: нужен генератор API Horizon.
- Прогресс, лог и отмена — через опрос `native_status`; отмена убивает группу
  процессов cargo вместе с rustc. Официальный лаунчер не нужен и не вызывается.
- Тот же сборщик доступен без окна:
  `gera-launcher --native-build <сборка> <мод> [--version v] [--allow-mismatch]` —
  удобно для проверки и для терминала.
- Java-моды несовместимы с Horizon.

## 6. Авторизация

Сейчас поддерживается офлайн-ник сборки (`--name`) и локальный скин. Microsoft-вход не
реализован: для него нужна регистрация приложения в Azure и OAuth-поток, которых у проекта
нет. GERA не имитирует вход и не обходит проверку владения игрой. Для подготовки ресурсов
используется легальная копия Minecraft Java Edition игрока; файлы игры GERA не скачивает.

## 7. Сеть и производительность

- Сеть — только по действию игрока: установка клиента, открытие каталога (кэш 10 минут),
  запуск диагностики. Фоновых таймеров нет.
- HTTPS — системный `curl`; хеши — `sha2`. Полный HTTP-стек не тянется.
- Ленивая загрузка страниц (`router.svelte.ts`).
- `uiMode` (лёгкий/тяжёлый) влияет только на CSS интерфейса и не читается кодом запуска игры.

## 8. Безопасность

- Удаление сборки убирает только запись; папка с мирами остаётся.
- Удаление мода делает резервную копию; миры и `options.txt` не трогаются.
- Запускается только `horizon-client` из найденной папки версии.
- Ссылки — только `https://`, внешние программы — `xdg-open` без shell.
- Ник валидируется (3–16 символов), пути должны быть абсолютными.
- Повреждённый `state.json` не теряется: файл переименовывается в
  `state.broken-<время>.json`.

# GERA Launcher — руководство

GERA — независимый лаунчер Minecraft на Rust (Horizon). Он сам устанавливает клиент
Horizon, готовит ресурсы из вашей легальной копии Minecraft, ставит контентные моды и
собирает нативные. Официальный Horizon Launcher не нужен.

## Если вы просто хотите поиграть

Короткий путь, без модов и сборок:

1. Запустите GERA.
2. **Настройки → Обновления → Установить сборку** → выберите обычную
   сборку (без слова `nightly`); если обычных нет — берите nightly. Дождитесь
   скачивания.
3. У этой версии нажмите **Подготовить** и укажите папку `.minecraft`.
   Нужен установленный **Minecraft Java Edition 26.3**, хотя бы раз запущенный
   официальным лаунчером: GERA берёт ресурсы из вашей копии игры и ничего не
   скачивает сам.
4. Дождитесь «ресурсы готовы».
5. **Главная → Играть**.

Всё. Сборку с ником GERA создаёт сама; ник можно поменять в разделе **Сборки**.
Моды, нативные сборки и остальные настройки на этом шаге не нужны.

### Вариант без официального лаунчера: Minecraft Java

Если официального лаунчера и папки `.minecraft` нет, GERA может поставить саму игру:

1. Откройте раздел **Java** в левом меню.
2. Впишите ник (3–16 символов, латиница, цифры, `_`) и нажмите **Играть**.
3. GERA скачает выбранную версию: клиент, библиотеки, нативные файлы, ресурсы
   и Java, если на ПК нет подходящей. Прогресс виден на экране.
4. Когда всё готово, игра запустится сама. Дальше кнопка **Играть** запускает
   её сразу.

Java не скачивается, если на компьютере уже есть подходящая версия — GERA
использует системную `java`. Ресурсы, библиотеки и Java хранятся один раз и
переиспользуются всеми версиями. Игровая папка открывается кнопкой **Папка игры**.

> Без лицензионной копии Minecraft поиграть не получится: лаунчер не содержит
> файлов игры и не обходит их проверку.

## 1. Установка и запуск

Готовая сборка — один бинарник.

Linux:

```sh
cp gera-launcher ~/.local/bin/gera-launcher
gera-launcher
```

Windows: запустите один файл `gera-launcher.exe` — рядом ничего не нужно.
Данные хранятся в `%LOCALAPPDATA%\gera-launcher\` (на Linux —
`~/.local/share/gera-launcher/`); системные настройки GERA не меняет.

Требования:

- Windows 10/11 — WebView2 (входит в систему) и `curl` (входит в Windows 10 1803+);
- Arch Linux / Omarchy (или совместимый дистрибутив), Wayland или X11;
- WebKitGTK для запуска (обычно уже есть в системе);
- для нативных модов дополнительно: `rust` и библиотеки Horizon
  (`vulkan-headers`, `alsa-lib`, `libxkbcommon`, `wayland`, `libx11`, `libxcursor`,
  `libxi`, `libxrandr`). На Windows нативная сборка требует установленный Rust
  и сборочные зависимости Horizon для Windows.

### Обновление лаунчера

GERA сам проверяет новые версии в GitHub Releases при запуске. Если есть
обновление, появляется окно «Доступна новая версия»:

- **Обновиться** — GERA скачает новый файл, сверит SHA-256 и перезапустится
  с новой версией;
- **Позже** — остаться на текущей версии до следующего запуска.

Проверить вручную можно в «Настройки → О программе → Обновления».
Сборки, серверы, моды и мир при обновлении не трогаются: заменяется только
файл лаунчера. Linux-бинарник обновляется так же, как Windows-exe.

Если GitHub недоступен, лаунчер просто запускается как обычно — ошибка
проверки не показывается.

## 2. Первый запуск

1. Откройте **Настройки → Обновления → Установить сборку**.
2. Выберите официальную сборку (release или nightly). GERA скачает её с GitHub,
   проверит SHA-256 и распакует в свою папку.
3. У сборки появится пометка «нет ресурсов» — нажмите **Подготовить**.
   `horizon-prepare` соберёт ресурсы из вашей копии Minecraft: укажите папку
   `.minecraft` (нужен Minecraft 26.3, хотя бы раз запущенный официальным лаунчером)
   и, если нужно, `server.jar`. Файлы игры GERA не скачивает.
4. Когда появится «ресурсы готовы», нажмите **Играть** на главной.

Если на компьютере уже лежит папка от официального лаунчера, GERA покажет её
как версию «на диске» — только для чтения. Она тоже подходит, если ресурсы готовы.

## 3. Клиент Horizon

В настройках, раздел **Обновления** и **Игровые настройки**:

- **Установить сборку** — список официальных релизов GitHub (включая nightly).
  Повторная установка той же версии не делается.
- **Версия для активной сборки** — «Авто» берёт новейшую готовую сборку, либо
  выберите конкретную (например, нативную сборку с модами).
- **Подготовить** — запускает `horizon-prepare` для версии без ресурсов.
- **Импорт готовых ресурсов** — берёт уже подготовленную папку с другого
  компьютера и копирует её в выбранную версию, без повторной подготовки.
- **Показать пути** — раскрывает полные пути к папкам версий.

Ресурсы лежат в `<версия>/.local/horizon-client/<Minecraft>/`. Признак готовности —
файл `asset-index.json`.

### Перенос ресурсов на другой ПК

Подготовку можно пройти один раз, а на втором компьютере просто скопировать
готовую папку:

1. На первом ПК возьмите `<версия>/.local/horizon-client/26.3` (около 700 МБ)
   и перенесите любым способом — флешкой, диском, облаком. Можно заархивировать
   её в zip: GERA понимает и папку, и архив.
2. На втором ПК установите клиент Horizon (шаг «Установить сборку»).
3. Перенесите ресурсы одним из способов:
   - **перетащите** папку или zip прямо в окно GERA;
   - положите папку или zip в `~/.local/share/gera-launcher/import/`
     (**Настройки → Импорт → Открыть папку**) и нажмите **Играть** на главной;
   - **Настройки → Хранилище → Импорт готовых ресурсов**: укажите путь
     вручную и выберите версию.
4. Появится «ресурсы готовы» — можно играть.

Принимается любая из папок: сама `26.3`, её родитель `horizon-client`, папка
версии с `.local/horizon-client/26.3` или zip с ними. Если ресурсы уже есть,
GERA откажется перезаписывать их. Неполная папка ресурсов заменяется целиком.

Архив или папка **Prism Launcher / MultiMC** (`instance.cfg`, `mmc-pack.json`,
`minecraft/` с настройками) ресурсами не является: в нём нет текстур, звуков и
моделей. GERA так и скажет — для игры нужна папка ресурсов около 700 МБ.

Папку `.minecraft` сюда указывать не нужно — это не готовые ресурсы, для неё есть
кнопка **Подготовить**. Импорт работает только с вашими собственными файлами
игры: GERA ничего не скачивает и не раздаёт.

Из терминала то же самое:

```sh
gera-launcher --import-resources <папка версии> <папка ресурсов>
```

## 4. Сборки

Сборка — это ник, игровая папка, версия клиента, скин и описание. У каждой сборки
свои миры, моды и настройки.

- **Главная → Создать сборку** или раздел **Сборки → Новая сборка**.
- Ник — офлайн-имя, оно передаётся игре как `--name`.
- Игровая папка: миры, настройки, `horizon-mods/` и логи. Существующие миры GERA
  не трогает.
- **Дублировать** создаёт копию: миры, моды, конфиги и настройки переносятся,
  а кэш, логи, скриншоты и резервные копии пропускаются.
- **Убрать из списка** удаляет только запись; папка с мирами остаётся на диске.
- Переключение сборки меняет активный ник и папку, но не удаляет ничего.

Скин — PNG в `<игровая папка>/skins/<ник>.png`; GERA передаёт его игре через
`HORIZON_OFFLINE_SKIN`.

## 5. Контентные моды (.hmod)

Раздел **Моды**, вкладка **Контентные**:

0. Сверху справа выберите сборку — мод установится именно в её игровую папку,
   даже если активна другая сборка. Список установленного тоже относится
   к выбранной сборке.
1. Найдите мод, откройте **Подробнее** или сразу **Установить**.
2. GERA скачает файл, проверит SHA-256 и положит его в
   `<игровая папка>/horizon-mods/`.
3. Обновление заменяет файл, удаление убирает его; перед этим старая версия
   копируется в `~/.local/share/gera-launcher/backups/mods/`.
4. Включите мод в игре: **Options → Mods**. По умолчанию установленные моды
   выключены — GERA не подделывает это состояние.

Русские описания в каталоге — перевод GERA (офлайн-словарь внутри лаунчера).
Полные тексты реестра остаются на английском и показываются ниже.

Блок **Встроенные моды** показывает нативные моды, которые уже находятся внутри
клиента Horizon (AppleSkin, Minimap, Zoom и другие). Это не файлы `.hmod`, поэтому
удалить их из GERA нельзя; включение и выключение — в игре, **Options → Mods**.
Счётчик модов на главной учитывает и контентные, и включённые встроенные моды.

## 6. Нативные моды (.hnmod)

Нативный мод меняет исходники самого Horizon, поэтому его нельзя «положить
файлом»: под него собирается отдельный клиент.

### Как это выглядит

1. **Моды → Нативные**, выберите сборку в списке сверху, затем мод и нажмите **Собрать**.
2. GERA покажет коммиты Horizon и horizon-mixins, базовую сборку, версию
   Minecraft и свободное место.
3. Прочитайте красное предупреждение: это нативный код, он выполняется с правами
   вашего пользователя. Нажмите **Начать сборку**.
4. Прогресс, лог и кнопка **Отмена** — в панели над списком модов. Отмена убивает
   cargo вместе с компиляторами.
5. Готовый клиент появится в разделе **Нативные сборки**. Кнопка **В сборку**
   переключает активную сборку на этот клиент.

### Что происходит внутри

1. Скачивается архив исходников Horizon на коммите из реестра
   (`native-1/<Horizon>/<mixins>` или `horizon-native.json`).
2. Собирается `horizon-mixins` нужной ревизии.
3. `horizon-mixins apply` применяет мод к копии исходников.
4. `cargo build -p horizon-client` компилирует игру.
5. Бинарник кладётся в `~/.local/share/gera-launcher/clients/native-<коммит>-<хеш>/`,
   а ресурсы базовой сборки подключаются симлинком `.local` — гигабайты не копируются.

### Сколько это занимает

- Первая сборка: примерно **30–90 минут** на слабом ноутбуке, 10–20 ГБ места.
- Повторная сборка другого мода заметно быстрее: исходники, инструмент и
  зависимости уже в кэше `native/`.
- На машинах с менее 6 ГБ памяти клиент собирается с пониженной оптимизацией
  (`opt-level=1`, один codegen-unit), а при нехватке памяти — без оптимизации.
  Зависимости при этом остаются оптимизированными.

### Ограничения

- Поддерживаются mixin-моды. Моды с trait-API (`[api]`) GERA отклоняет с
  объяснением: нужен генератор API Horizon, которого в GERA нет.
- Мод привязан к коммиту Horizon. Если базовая сборка — другой коммит, GERA
  предупредит и попросит галочку **«Собрать всё равно»**. Мод может не примениться.
- Нативный мод встроен в клиент постоянно; отдельного переключателя нет.
- Один клиент — один набор модов. Другой набор = ещё одна сборка.
- Удаление сборки убирает только папку GERA; базовая версия, ресурсы и миры
  остаются. Если сборка играет на этом клиенте, GERA сначала попросит выбрать другую.

### Сборка из терминала

Тот же сборщик без окна:

```sh
gera-launcher --native-build <сборка> <мод> [--version 0.3.2] [--allow-mismatch]
```

Пример:

```sh
gera-launcher --native-build default veinminer --allow-mismatch
```

Прогресс печатается в stdout, в конце — `ГОТОВО: <папка>`.

## 7. Настройки

- **Внешний вид** — системная, светлая или тёмная тема, включение градиентов
  и предпросмотр палитры. Без градиентов шапка, плитки и значки заливаются
  ровным цветом.
- **Цвета** — Dynamic Color: восемь готовых палитр и свой акцент. Из одного
  цвета Material You строит Primary, Secondary, Tertiary и поверхности.
  Выбор сохраняется в настройках GERA.
- **Производительность интерфейса** — Light (минимум анимаций и эффектов,
  меньше нагрузки) или Heavy (полные анимации, размытия, переходы). Режим влияет
  только на лаунчер, не на игру; при системном `prefers-reduced-motion` анимации
  отключаются в любом режиме.
- **Игровые настройки** — версия клиента для активной сборки, папка Minecraft
  для подготовки ресурсов, server jar, готовность сборщика нативных модов.
- **Хранилище** — папка лаунчера, импорт готовых ресурсов, своя папка версии.
- **Обновления** — установка официальных сборок Horizon с GitHub.
- **О программе** — версия, ссылки, лицензии и диагностика по кнопке.

## 8. Где что лежит

| Что | Путь |
|---|---|
| Данные GERA | `~/.local/share/gera-launcher/` |
| Клиенты GERA | `~/.local/share/gera-launcher/clients/` |
| Нативные сборки | `.../clients/native-<коммит>-<хеш>/` |
| Кэш сборки | `.../native/` (исходники, инструмент, target) |
| Резервные копии модов | `.../backups/mods/` |
| Логи GERA | `.../logs/` (см. пункт ниже) |
| Настройки и сборки | `.../state.json` |
| Установленные моды | `.../mods-state.json` |
| Игровая папка сборки | как указано в сборке |
| Контентные моды | `<игровая папка>/horizon-mods/` |

Логи разделены по этапам, все лежат в `.../logs/`:

| Файл | Что внутри |
|---|---|
| `launcher.log` | запуск GERA, версии, проверка обновлений |
| `assets-download.log` | метаданные Mojang, клиент, библиотеки, ресурсы |
| `import.log` | импорт ресурсов с другого ПК |
| `prepare.log` | вызовы `horizon-prepare`: команда, код выхода, вывод |
| `game-launch.log` | точная команда запуска и как игра завершилась |

Формат строки: `время UTC | уровень | этап | сообщение`. Пароли и токены
не пишутся: их в лаунчере нет.

## 9. Если что-то не работает

**«Клиент Horizon не найден».** Установите сборку в настройках и подготовьте
ресурсы.

**«Ресурсы не подготовлены».** Нажмите **Подготовить** у версии. Нужна папка
Minecraft 26.3, запущенная хотя бы раз официальным лаунчером.

**Игра не стартует или закрылась сразу.** GERA показывает последние строки лога
и путь к файлу. Дальше: **Настройки → Диагностика** и кнопки **Открыть папку
логов**, **Открыть последний лог**, **Скопировать отчёт**. Частые причины:
нет Vulkan-драйвера, не готовы ресурсы (нажмите **Проверить** у версии в разделе
Java), неверный ник.

**Не скачиваются ресурсы.** Нажмите **Повторить загрузку**: уже проверенные
файлы повторно не скачиваются, недокачанные продолжаются с места обрыва.
Подробности пишутся в `assets-download.log`.

**Импорт ресурсов не принимается.** GERA показывает конкретные отсутствующие
файлы. Можно докинуть готовую папку `horizon-client/<версия>` или папку
`.minecraft` целиком: во втором случае ресурсы подготовит `horizon-prepare`.

**Сборка нативного мода падает.** Смотрите лог в панели сборки. Чаще всего:
мод сделан для другого коммита Horizon (нужна галочка «Собрать всё равно»),
не хватает Rust, мало места или памяти. Отмена и повтор безопасны:
кэш остаётся, готовые шаги не пересобираются.

**«Мало места».** Нужно минимум 12 ГБ свободно. Кэш можно удалить вручную:
`~/.local/share/gera-launcher/native/target` (пересоберётся) и
`.../native/cache`.

**Мод установился, но его нет в игре.** Включите его в **Options → Mods**.
Контентные моды по умолчанию выключены.

## 10. Чего GERA не делает

- Не распространяет файлы Minecraft: клиент, библиотеки и ресурсы скачиваются
  с официальных серверов Mojang и проверяются по SHA-1, а ресурсы Horizon
  готовятся из вашей собственной копии игры.
- Не требует и не запускает официальный Horizon Launcher.
- Не трогает миры, сборки и моды без резервной копии и подтверждения.
- Не подделывает вход Microsoft: сейчас только офлайн-ник. Для входа нужен
  Azure client ID и OAuth, которых у проекта нет.
- Не включает моды за вас и не меняет их состояние в игре.
- Не устанавливает системные пакеты без вашего участия.

## 11. Сборка из исходников

Linux: нужны Rust, Node.js и WebKitGTK.

```sh
sudo pacman -S --needed rust nodejs npm webkit2gtk-4.1
npm install
npm run tauri dev
```

Релиз:

```sh
npm run tauri build -- --no-bundle
```
